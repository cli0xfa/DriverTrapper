# DriverTarpper

Windows 内核驱动加载取证工具。项目由一个管理员权限运行的控制台程序和一个内核驱动组成：驱动监视内核映像加载，用户态程序接收事件、记录路径并提示文件复制位置。

## 项目结构

| 路径 | 说明 |
| --- | --- |
| `dt/` | 用户态控制台程序。释放并启动驱动，接收通知，转换文件路径并显示 Windows Toast。 |
| `kdt/` | 内核驱动源码及 INF 安装包配置。注册映像加载回调、维护事件队列，并尝试复制加载映像对应的磁盘文件。 |
| `driver-tarpper.slnx` | Visual Studio 解决方案，包含 `dt` 和 `kdt` 两个项目。 |

## 工作流程

1. `dt.exe` 在 `C:\DriverDump` 创建工作目录。
2. 程序从自身资源中提取 `kdt.sys` 到 `C:\DriverDump\kdt.sys`，清理旧的 `kdt` 服务后创建并启动内核驱动服务。
3. 用户态程序打开 `\\.\kdt`，注册事件句柄并等待驱动通知。
4. 驱动使用 `PsSetLoadImageNotifyRoutine` 监视映像加载。当前回调只处理 `ProcessId == 0` 的事件；它将路径放入队列并通知用户态，同时排队尝试把源文件复制到 `C:\DriverDump`。
5. 用户态程序输出加载路径和预期复制位置，并显示通知。点击通知会在资源管理器中定位对应路径。
6. 按 Ctrl+C 后，程序尝试停止并删除驱动服务，随后删除释放出的 `kdt.sys`。

这里的“取证”是对加载映像对应的磁盘文件进行复制，不是从内存中转储映像。多个源文件若具有相同文件名，目标路径可能冲突并被覆盖。

## 构建

需要安装 Visual Studio C++ 桌面开发工具、Windows SDK 和 Windows Driver Kit (WDK)。项目使用 C++20，驱动项目配置为 KMDF。

两个项目的最终产物统一输出到解决方案根目录下的 `<平台>/<配置>/`，例如 `x64/Release/`。`dt` 项目引用 `kdt` 项目，因此构建 `dt` 时会先构建驱动；资源脚本通过构建配置取得同一输出目录中的 `kdt.sys` 并嵌入 `dt.exe`。

当前解决方案将用户态项目映射到 x64，完整的打包运行目标是 x64；驱动项目自身还声明了 ARM64 配置，但解决方案中的 ARM64 用户态/驱动配对尚未配置完整。

驱动项目配置为 KMDF，但源码有意采用 WDM 风格实现（例如 `DriverEntry`、IRP 派发和 `IoCreateDevice`）。这是项目的设计选择，不是需要修正的配置错误。

运行驱动还受 Windows 内核驱动签名策略约束。请使用目标环境认可的签名和部署方式；仅成功编译并不代表驱动一定能在当前系统加载。

## 运行

以管理员身份运行构建出的 `dt.exe`。程序启动后会在控制台显示监控状态；按 Ctrl+C 停止监控并触发清理。

程序会修改系统服务管理器中的 `kdt` 驱动服务，并在固定的 `C:\DriverDump` 路径释放驱动、保存捕获文件。请只在有授权的测试或取证环境中运行，并在运行前检查该服务名和目录是否已被其他程序使用。

## 当前实现注意事项

- INF 中的 `DriverVer` 和厂商名称仍是模板占位内容。
- 驱动复制文件是异步尝试，用户态日志显示的目标路径不代表复制已成功。
- 驱动和用户态程序使用相同的 IOCTL 定义，分别用于注册事件和读取加载路径。
